FOOD FRESHNESS IDENTIFIER
Complete Project Plan
============================================================

1. PROJECT OVERVIEW
------------------------------------------------------------
Project Name:
Food Freshness Identifier

Project Type:
Deep Learning + Computer Vision + Reinforcement Learning

Domain:
Agriculture & Food Technology

Primary SDG:
SDG 12 – Responsible Consumption and Production

Main SDG Target:
Target 12.3 – Reduce food loss and food waste.

Project Duration:
8 Weeks (2 Months)

Main Goal:
To develop an AI-based system that analyzes images of perishable food items,
identifies their freshness level, detects early signs of spoilage, and provides
a simple recommendation such as "Fresh", "Consume Soon", or "Discard".

The main intelligence of the project will come from Deep Learning. A small
Reinforcement Learning component will be added as a decision layer to determine
the appropriate next action based on the freshness prediction and confidence.


2. PROBLEM STATEMENT
------------------------------------------------------------
Food is often thrown away because people are unsure whether it is still fresh,
especially when visible spoilage is at an early stage. In many situations,
people depend only on appearance or printed dates, which may not accurately
represent the current condition of the food.

The proposed system will use a camera image of a food item and a Deep Learning
model to identify the food type and estimate its freshness stage.

The system will classify food into stages such as:

1. Fresh
2. Early Deterioration
3. Moderately Deteriorated
4. Spoiled

The system will then produce a freshness score and recommendation.

Example:

Food Type: Tomato
Freshness Score: 78%
Stage: Early Deterioration
Confidence: 93%
Recommendation: Consume Soon

The project is intended as an AI decision-support system and should not be
treated as a laboratory-grade food safety test.


3. CORE IDEA
------------------------------------------------------------
The project should NOT be designed as a simple "Fresh or Spoiled" classifier.

The stronger approach is to identify a gradual freshness transition:

Fresh
  ↓
Early Deterioration
  ↓
Moderate Deterioration
  ↓
Spoiled

This makes the project more useful because the system attempts to identify
changes before severe spoilage becomes obvious.

The system can also store observations of the same food item over multiple
days so that freshness can be tracked over time.

Example:

Day 1 → 96% freshness
Day 2 → 91%
Day 3 → 83%
Day 4 → 70%
Day 5 → 52%

This creates a freshness trend that can later be used for an approximate
remaining-freshness estimate.


4. OBJECTIVES
------------------------------------------------------------
Primary Objectives:
- Build a Deep Learning model for food freshness classification.
- Detect early visual signs of deterioration.
- Generate a freshness score and confidence score.
- Support multiple common food categories.
- Provide a simple recommendation based on the prediction.
- Add a small Reinforcement Learning decision layer.
- Track freshness changes over time for repeated observations.

Secondary Objectives:
- Create a clean user interface for image upload or camera input.
- Display model predictions clearly.
- Visualize freshness trends using charts.
- Evaluate the model using suitable classification metrics.
- Create an explainable prediction using techniques such as Grad-CAM.


5. SCOPE OF THE FIRST VERSION
------------------------------------------------------------
To keep the project realistic for two months, the first version should focus
on only 3 to 5 food categories.

Recommended starting categories:
- Banana
- Tomato
- Apple
- Potato
- Bread

The team should not attempt to support every type of food.

The first version should focus on image-based freshness assessment under
controlled or reasonably consistent lighting.

A later version can support more food types and additional sensing methods.

7. DEEP LEARNING COMPONENT – CORE OF THE PROJECT
------------------------------------------------------------
Deep Learning must be the main part of the project.

Recommended approach:
Use Transfer Learning instead of training a large model from scratch.

Recommended models:
- EfficientNet-B0 or EfficientNet-B2
- ResNet50
- MobileNetV3 for lightweight deployment

Primary recommendation:
EfficientNet-B0 is a good starting point because it provides a strong balance
between accuracy, speed, model size, and ease of deployment.

Model input:
A food image resized to the required input size.

Model output:
- Food category
- Freshness stage
- Class probability / confidence

Possible output classes:
Fresh
Early Deterioration
Moderate Deterioration
Spoiled

A separate food-type model may be used if required, but the first version can
also use one model with combined labels such as:
Tomato_Fresh, Tomato_Early, Tomato_Moderate, Tomato_Spoiled, etc.

A better scalable design is:
Model 1 → Food type
Model 2 → Freshness stage

However, for a two-month project, the team can initially start with a single
classification model and split the architecture later if needed.


8. IMAGE PREPROCESSING
------------------------------------------------------------
Images should be standardized before being sent to the model.

Typical preprocessing:
- Resize image
- Normalize pixel values
- Convert to the required color format
- Optional background cropping
- Data augmentation during training

Useful augmentation:
- Horizontal flip
- Small rotation
- Random crop
- Brightness variation
- Contrast variation
- Slight zoom

Augmentation is important because real-world food photos will not always have
the same lighting or camera angle.


9. DATASET PLAN
------------------------------------------------------------
Two data sources can be combined:

A. Public datasets
Use suitable publicly available food freshness / fruit quality / food
classification datasets for initial training.

B. Custom dataset
Create a smaller original dataset by photographing selected food items over
several days.

The custom dataset is an important part of the project because it makes the
project more original and demonstrates real data collection.

Recommended collection process:

Day 0 → Fresh sample
Day 1 → Same sample photographed
Day 2 → Same sample photographed
Day 3 → Same sample photographed
Day 4 → Same sample photographed
...
Continue until visible deterioration.

For each sample, keep:
- Food type
- Date
- Day since observation
- Storage condition
- Image
- Freshness label
- Optional notes about visible changes

Important:
The team should follow consistent storage and photography conditions as much
as possible.

Do not make food safety claims based only on visual appearance.


10. DATA LABELING
------------------------------------------------------------
Define clear labeling rules before training.

Example:

Class 1 – Fresh:
Normal appearance, no major visible deterioration.

Class 2 – Early Deterioration:
Small visual changes such as slight browning, softening, wrinkles, or color
change.

Class 3 – Moderate Deterioration:
Clearly visible quality reduction, larger discoloration or structural changes.

Class 4 – Spoiled:
Strong visual evidence of severe deterioration, mold, major discoloration,
or clearly unacceptable visual condition.

The labeling criteria should be documented so all team members use the same
rules.


11. DATA SPLITTING
------------------------------------------------------------
Use three main subsets:

Training set:
Used for model learning.

Validation set:
Used to tune hyperparameters and monitor overfitting.

Test set:
Used only for final evaluation.

Recommended initial split:
70% Training
15% Validation
15% Testing

Important:
Images of the exact same physical food item should not be randomly distributed
across training and test sets because this can cause data leakage.

For time-series photographs of the same item, keep the item grouped into one
split.


12. MODEL TRAINING
------------------------------------------------------------
Training steps:

1. Load the dataset.
2. Apply preprocessing and augmentation.
3. Load the pretrained model.
4. Replace the final classification layer.
5. Freeze most pretrained layers initially.
6. Train the new classification head.
7. Unfreeze selected upper layers.
8. Fine-tune with a small learning rate.
9. Monitor validation performance.
10. Save the best model.

Recommended loss:
Cross-Entropy Loss for multi-class classification.

Recommended optimizer:
Adam or AdamW.

Important metrics:
- Accuracy
- Precision
- Recall
- F1-score
- Confusion matrix

Because some freshness stages may be harder to detect than others, F1-score
and confusion matrix should be examined rather than relying only on accuracy.


13. FRESHNESS SCORE
------------------------------------------------------------
A simple freshness score can be generated from model probabilities.

Example conceptual mapping:

Fresh = 100
Early Deterioration = 70
Moderate Deterioration = 40
Spoiled = 0

A weighted probability score can then be calculated using the class
probabilities.

Example:

Fresh probability = 0.70
Early probability = 0.20
Moderate probability = 0.08
Spoiled probability = 0.02

The resulting score can be mapped to a 0–100 scale.

This score is an AI-derived indicator, not a laboratory measurement.


14. CONFIDENCE SCORE
------------------------------------------------------------
Display the confidence of the model prediction.

Example:

Freshness:
Early Deterioration

Confidence:
93%

A confidence threshold can be used.

For example:
High confidence → provide normal recommendation.
Low confidence → request another image or manual inspection.

The exact threshold should be selected using validation data rather than
arbitrarily.


15. REINFORCEMENT LEARNING COMPONENT
------------------------------------------------------------
Reinforcement Learning should remain a smaller supporting component.

The RL agent should NOT replace the Deep Learning freshness model.

Its role:
Choose the next action based on the AI prediction.

Possible actions:
- Continue storage
- Recheck later
- Consume soon
- Recommend manual inspection
- Remove/discard

Example state:

Food type
+
Freshness stage
+
Confidence
+
Freshness trend
+
Days observed

The RL agent chooses an action.

Simple example:

State:
Tomato
Early Deterioration
78% freshness
92% confidence

Action:
Consume Soon

Another example:

State:
Unknown food appearance
Low confidence

Action:
Request Another Image

The RL component can be implemented using a small environment built specifically
for this project. PPO or Q-learning/DQN can be considered. Since the action
space is small, a simple DQN or tabular Q-learning prototype may be sufficient.

The RL environment can be simulated because real-world trial-and-error on
actual food is not necessary for the project.


16. HOW RL CAN BE TRAINED
------------------------------------------------------------
Create a simulated decision environment.

State:
- Freshness score
- Freshness class
- Confidence
- Days since first observation
- Freshness trend

Actions:
1. Continue storage
2. Recheck
3. Consume soon
4. Manual inspection
5. Remove

Reward examples:
- Appropriate recommendation → positive reward
- Unnecessary inspection → small negative reward
- Delayed action for highly deteriorated food → larger negative reward
- Good use of high-confidence information → positive reward

The reward values are design choices for the simulation and should be explained
clearly in the project report.

The goal is to show that the RL layer learns an action policy from the outputs
of the Deep Learning model.


17. FRESHNESS TREND MODULE
------------------------------------------------------------
For repeated images of the same item, store:

Date

Predicted freshness score
Predicted class
Confidence

Then plot the freshness score against time.

Example:

Day 1 → 96
Day 2 → 90
Day 3 → 81
Day 4 → 70
Day 5 → 55

This enables a simple trend estimation.

A small regression or time-series model can later be added to estimate
approximate remaining freshness time.

This feature is optional for the MVP but highly recommended for a stronger
hackathon demonstration.


18. EXPLAINABLE AI
------------------------------------------------------------
Use Grad-CAM or a similar explainability method to show which regions of the
image influenced the Deep Learning prediction.

Example:

Original image

Grad-CAM heatmap

Highlighted region around browning / bruising / visible deterioration

This makes the model easier to demonstrate and can help judges understand
that the model is using relevant visual features.

28. POSSIBLE CHALLENGES
------------------------------------------------------------
Challenge 1:
Different lighting can change food appearance.

Solution:
Use augmentation and collect images under different lighting conditions.

Challenge 2:
Different food varieties may look different.

Solution:
Start with a limited number of categories and expand later.

Challenge 3:
Freshness labels are subjective.

Solution:
Define clear labeling rules and use repeated observations.

Challenge 4:
Model may learn background instead of food.

Solution:
Use clean backgrounds, cropping/segmentation where possible, and test on
different backgrounds.

Challenge 5:
RL may be difficult if the environment is poorly designed.

Solution:
Keep the RL action space small and use a simulated environment.

Challenge 6:
The project may become too large.

Solution:
Prioritize the Deep Learning freshness classifier first. Add optional modules
only after the core system works.


29. WHAT NOT TO DO
------------------------------------------------------------
Do not:
- Train a huge model from scratch.
- Support dozens of food categories at the beginning.
- Depend on expensive sensors for the MVP.
- Claim that image prediction guarantees food safety.
- Make RL responsible for image classification.
- Spend most of the project on UI.
- Collect a huge dataset before building a working baseline.
- Use the same physical food samples in both training and testing.
